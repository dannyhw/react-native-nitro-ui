## Must fix

**M1. A completion launders the run it completes: a relaxed, older-version or other-judge red
becomes a clone-wide green.**

- `scripts/gate.mjs:1854-1855` records `relaxed` and `judge` from the completion's own process.
- `completeRerun` (`scripts/gate-core.mjs:2448`) merges the base run's unit results without
  reading `base.relaxed`, `base.judge` or `base.v`.
- `foreignVerdict` (`gate-core.mjs:913-916`) checks only the completion line.

So most of the gate's units come from a run that was relaxed, written by an older ledger
version, or judged by other gate code. Re-running one failed unit with a clean shell then gives a
green that every branch accepts. Scenarios 5 and 6 show it. The concrete false green:

1. Run `harness:ios` with `NITRO_UI_ALLOW_UNSTAMPED=1`, against whatever app the simulator has.
2. One suite fails.
3. Run `--rerun-failed` in a clean shell. It is green, and the row on every branch on these files
   reads `**PASS** (completed …; from task/x)`.

The fix: a completion line inherits from its base run.

- `relaxed`: the base's switches merged with the completion's own. Use `null` when the base
  has none recorded or when `base.v !== LEDGER_VERSION`.
- `judge`: `before.judge` only when it equals `base.judge`, else `null`.

On its own branch nothing changes, and `isUnrelaxed(null)` already refuses such a line elsewhere.
Update `gates.md` "Runs from other branches" to say that a completion counts elsewhere only when
the run it completed would have. Red proofs: scenarios 5 and 6 as unit tests, with the
inheritance removed.

**M2. `RELAXING_SWITCHES` (`gate-core.mjs:44-55`) misses switches that change what a run tests.**

- **`NITRO_UI_HARNESS_ISOLATED=1`** (the definite false green):
  - `gate.mjs:1591` passes the shell's environment to the child, and `scripts/harness.mjs:89`
    passes it on to the shared run.
  - `example/jest.harness.config.mjs:5` then selects only `__tests__/isolated/`, which is 3 of
    the 34 harness files, and `harness-isolated.mjs:39` skips the second run.
  - The gate's result (`gate.mjs:1782`) depends only on the exit code. A shell left with the
    variable exported, for example after debugging an isolated suite, records a full
    `harness:<p>` **pass** with `relaxed: {}`. That pass counts on its own branch, which was
    already the case, and now on every branch.
  - Fix: since this is `harness.mjs`'s own internal switch, delete it from `childEnv` for device
    gates, or refuse the gate when it is set. Do not merely list it. Red proof: a CLI test with
    it exported records a full run that ran only the isolated files.
- **`NITRO_UI_TEST_TZ`, `NITRO_UI_TEST_LOCALE`, `NITRO_UI_TEST_LANGUAGES`**
  (`example/rn-harness.config.mjs:202-216`, `scripts/app-launch-env.mjs`):
  - The pinned `Europe/Lisbon` exists so the DST round trip is exercised. `NITRO_UI_TEST_TZ=UTC`,
    or an empty value ("ask the device"), skips that exercise and lets a DST regression pass.
  - The locale is partly caught by the size table without `NITRO_UI_ALLOW_LOCALE_MISMATCH`. The
    zone is not caught at all.
  - Add all three. For these, a set but empty value is a relaxation too, but
    `relaxedSwitches` (`gate-core.mjs:66`) treats `''` as unset.
- **`CI`** on the list is fine:
  - `check` is never foreign, CI evidence is out of scope, and both CLI suites scrub it
    (`gate-evidence.test.js:440`, `gate-rerun.test.js:510`).
  - It over-matches `CI=0` or `CI=false`, which refuses evidence but never proves anything.
  - I checked the rest and none needs listing. `HARNESS_APP_PATH` is stamp-checked
    (`real-input/android.mjs:399`, `rn-harness.config.mjs`). The `IOS_*` and `ANDROID_*`

**M3. `check` is now flaky: `gate-rerun.test.js` "…leaves a unit unreported…" fails under full
load.**

- `gate-rerun.test.js:739` asserts the launcher's own `(exit 1)`. That message appears only when
  the background child finishes inside the launcher's 750 ms window (`gate.mjs:1015`).
- One gate CLI call takes about 0.6 to 1 s even when the machine is idle: the test takes 2.3 s
  for its three calls.
- In the clone's log store, this test passed in all 11 full `check` runs before the fix round
  and failed in 3 of the 4 after it: 21:32 on this branch, 21:44 on `task/M11-…`, and mine at
  21:44.

  test's own, and it predates this task (`fc030f46`).
- It now blocks `check`, and with it `need --for review` and `need --for merge`, about three
  times in four.
- The fix, from this evidence, without loosening an assertion: split the test into two
  deterministic variants.
  - The fake runner holds until the launcher has handed off. Assert launcher exit 0, then that

  - The "finished before hand-off" message is covered by a unit test of that branch, not by a
    race.
