## Summary

`ci.yml` has one `real-input-android` job ("Real input (Android)"), `workflow_dispatch` only:
the trial job without its matrix and capture-timing probe, keeping the failure capture, the
whole-run `events-system.txt` log and the 63-minute hosted ceiling in
`scripts/real-input/android.mjs`. The job runs the suite through `scripts/gate-ci.mjs`, which
records each run (exit, times, relaxing switches, SHA) beside the units file and e2e's output.
When the full run is red, the job re-runs once, choosing units with `rerunOfUnits`, the code
`--rerun-failed` now uses too. It uploads both runs as `real-input-android`, the logs as
`real-input-android-logs`. A final `verdict` step judges the upload the way the import will.

`node scripts/gate.mjs ci-import --run <id>` reads with `gh` (run, jobs, artifacts, download)
and writes one `real-input:android` line. It refuses, recording nothing, for a head SHA that is
not `HEAD`, uncommitted changes, an unfinished run or job, another workflow, no job of that
exact name, an attempt already in the ledger, or a missing upload. The verdict comes from the
upload, never the job conclusion. `recordResults` re-judges the e2e report, quarantines
included. A control passes only when the units file and the report agree, the run exited 0,
and the record and report are of `HEAD`. A red full run the job re-ran becomes one completion
line through `planRerunFailed`, `completeRerun` and `completionProvenance`, when the re-run
named exactly what a completion would. Otherwise the re-run is not counted.

Decisions a reviewer should check:

- The CI line records `relaxed` from the job's record, minus `CI` and `GITHUB_ACTIONS` (the
  hosted ceiling the brief accepts). Any other relaxing switch is kept, so such a line counts
  only on its own branch. `GITHUB_ACTIONS` is now a relaxing switch for local runs, because it
  lengthens the ceiling.
- `LEDGER_VERSION` is 9 (lines carry `source`). The `scripts/gate-ci*.mjs` files are on the
  tooling list and in `JUDGE_FILES`. Editing gate code already changes the judge digest, so
  this merge owes all four device gates. `need --for merge` lists them.
- The trial artifacts hold no units file, so the fixtures' `units.json` is rebuilt from the
  same jobs' logs (control PASS/FAIL lines, auxiliary check ids). Reports are cut to the fields
  the verdict reads (24 KB each).

Docs: `docs/agents/gates.md` "Runs on CI", `AGENTS.md` definition of done, and the
orchestrate skill's merge steps. Push and dispatch stay with whoever may write to GitHub.
