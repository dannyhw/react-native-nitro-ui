## Summary

The out-of-front wait before each fresh launch now also waits until `dumpsys activity
activities` lists no `ActivityRecord` of the app, and names any record left at its 30 s
deadline. On hosted run 45696813933 the app's record outlived the process and the focus move by
about 3 s, until the window manager finished the close transition. The driver's own close reads
the foreground app from that record (its `dumpsys activity` tier) and allows 2 s.

On the leased API 35 emulator, the real report lists the running app as
`ActivityRecord{1f1236b u0 nitroui.example/.MainActivity t3615}`, and right after a stop as
`* Hist  #0: ActivityRecord{1395820 u0 nitroui.example/.MainActivity t3618 f} isExiting}`.
The parser reads both, and the record was gone 0.74 s after the stop in each of three rounds. So
locally the wait adds under a second per fresh launch.

The filtered `bottom-sheet` run passed on the tree before the type declaration for the new
device read was added (`app-leaves-front.d.mts`, which no run executes), so its row prints as
stale. The merge's full run covers the final tree.
