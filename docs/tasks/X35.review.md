## Confirmed

- Real touches. `locator.tap()` becomes agent-device `press @ref`, which resolves to a point and sends `{action:'input', input:{kind:'tap', x, y}}` to the on-device instrumentation helper, falling back to `adb shell input tap` (`agent-device/dist/src/mechanics.js`). The helper's dex has `UiAutomationInputDispatcher`, `TouchPlanInjector` and `injectInputEvent` with `MotionEvent`. Its `performAction` strings sit with the fill and scroll handlers; the suite types with `pressSequentially`, not `fill`. So a tap is an input event, not an accessibility click. This rests on strings in a compiled APK, not on decompiled code.
- Device boundary. One serial from the lease, `-P` and `-s` on every adb call, `AGENT_DEVICE_ANDROID_DEVICE_ALLOWLIST` set to that serial (read in `device-isolation.js`), a daemon in `.real-input/android/agent-device` bound to 127.0.0.1 on an ephemeral port, stopped with the tool's own `daemon stop` before and after the run. The state dir holds `daemon-shutdown.json` and no `daemon.json`. A killed run leaves the daemon to its 5-minute idle timeout. No `pkill`, `killall`, `kill-server` or 5037.
- Package. `e2e` 0.23.1 and `@e2e-dev/mobile` 0.12.7 are exact dev dependencies of `example/` only; root `package.json`, `etc/`, `src/`, `android/`, `ios/` have no diff. `tsconfig.json` adds `example/e2e` to the dev typecheck; the build uses `tsconfig.build.json` (`include: ["src"]`). The lockfile keeps the harness runtime on `@vitest/expect` 4.0.16.
- Untouched: `example/ios`, `scripts/real-input/ios.mjs`, `example/__tests__`. `retries` is 0 in config and on the command line; no `agent.act` or `agent.assert`; no skips.
- All 70 harness citations in the report resolve to the named test at the cited line. Eight rows opened (switch, slider, picker, date-picker, bottom-sheet, context-menu, popover, form): each cited test asserts the echo-count behaviour the row lists. The gaps are what the rows leave out.
