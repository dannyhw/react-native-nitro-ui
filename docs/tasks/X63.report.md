# X63 — the Android a11y sweep scrolls until its control is on screen or the page ends

## Summary

`treeShowing` in `scripts/real-input/a11y-sweep.mjs` no longer stops after a fixed eight swipes.
It grades a case on the first dump in which the control's named node has a box wholly inside the
window (bottom edge strictly above the window's bottom: `uiautomator` clips at the edge, so a box
ending on it may be cut off), or on the dump after a swipe that moved nothing (same class,
resource id, name and box for every node, before and after). A missing or zero-sized control
still fails with today's finding, once the page has ended.

The navigation object gains `windowHeight` (the device passes `size().height`); the probe refuses
a navigation without one rather than calling every box on screen.

`SCROLL_PROBE_LIMIT` is now 400 and only stops a page that changes on every dump; reaching it
fails the case with its own `✗` line ("still moving after 400 swipes"), and the last dump is
still graded. The number comes from measuring the screens on this machine's Pixel 9 image:
`HostScreen` scrolls about 7,200 px (20 swipes), `DatePickerScreen` about 11,700 px (33), and
the Switch, Slider, Button, Segmented and Picker screens end in a 200-row list of 95–131 px rows,
roughly 30,000–40,000 px. A local swipe moves the page about 350 px; 400 swipes reach 40,000 px
at 100 px a swipe. The old comment's "2,560 px is more than the longest screen" was false for
every one of those screens; it only held for the hosted cases because they sit high on
`HostScreen`.

Merge with `task/X62-a11y-sweep-evidence`: checked with `git merge-tree`. `a11y-sweep.mjs` and
`a11y-sweep.d.mts` merge cleanly (the probe's first doc line is kept as it was, so X62's
`evidence` function lands above it). `a11y-sweep-device.mjs` conflicts on one import line, but
that conflict is between `main` (`readWindowFocus`) and X62, and appears without this branch too.
