# X68 — the press-feedback check times its frames by the device's clock

**Branch:** `task/X68-press-feedback-raw-frames` (from `main` at `57de0ed4`) · **Round:** 1 of up to 3 ·
**Lease:** `X68-e9f58` (`emulator-5570`)

## Summary

The host-clock bound that X67 added (a frame counts if its read finished within the 1800 ms
hold) failed on hosted runners, where a `screencap -p` took 1.4 to 2.1 s. No frame counted,
though the frames showed the ink. A capture-timing probe over three hosted jobs measured 130 to
1990 ms for a PNG and 40 to 1270 ms for a raw frame cut on the device, so no faster transfer
makes a host-clock bound safe.

Frames are now timed on the device. Each frame is a raw RGBA `screencap` written to a file on
the device, `/proc/uptime` is read once it has been taken, and only the sampled rows cross adb.
After the press, the lift's time is the newest touchscreen `action=UP` in `dumpsys input`'s
recent events (monotonic nanoseconds). A frame counts only if the device took it at least one
`/proc/uptime` step (10 ms) before the lift. `/proc/uptime` is the boot-time clock, which never
runs behind the monotonic one, so the comparison can only make a frame look later than it was.
Frames before the landing show the box at rest and count for nothing. A press with no lift in
the dispatcher's events is red and says so.

Frames are read for the whole press, from the moment it is issued. The hold, the minimum drop,
the sample grid (24 px in from each edge, every 8 px) and the ink-clears check are unchanged.
The PNG capture had no other caller and is gone.
