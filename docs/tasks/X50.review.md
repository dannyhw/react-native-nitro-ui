## Must fix

**M1. A branch whose own newest run on the digest is red still gives other branches a green.**
`scripts/gate-core.mjs:786` drops every red line from the clone-wide record before anything is
compared, and `:855` takes any accepted green. The in-branch rule (the newest decisive line wins)
is never applied to the branch that recorded the lines. A probe against `gateRowFor` with two
lines from `task/t` on one digest, green at 10:00 and red at 12:00, returned `red` from
`task/t`'s own ledger and `green (from task/t)` for any other branch. Two ways this happens:

- **The merge flow.** A task branch re-runs a gate and goes red on files it had passed. Its own
  `need` says red, and a merge branch on the same files says green.
- **The same branch in a new worktree.** After the task's worktree is removed, a new worktree on
  the same branch has an empty `.gates/`. The old red is in the record and is ignored, so the
  claim in `docs/agents/gates.md:134` that a red run here is not hidden only holds while the
  worktree exists.

Before this change both cases read as missing. The fix:

- Group foreign lines by the branch they came from. Apply `gateRowFor`'s own rule within each
  group, with `foreignProofKey`'s strictness, to full unmoved runs of either result on the
  current digest.
- A branch counts only when its newest such line is green.
- Read the clone-wide lines of the current branch as own lines, deduplicated against
  `.gates/<branch>.jsonl` by `ts` + `logPath`.
- Red proofs: the probe above as a unit test, and a CLI test that removes a worktree whose
  newest line is red.
- Update `gates.md` "Runs from other branches" to state the rule.

**M2. `check` from another branch counts on a tree whose checked files differ.**
`gate-core.mjs:804` compares `entry.tree`, the full code tree from `currentCodeTree`.
`isCodeFile` (`scripts/app-stamp-core.mjs:44-56`) leaves out `bench/`, `docs/`, `.github/`,
`.vscode/` and every `*.md`. `check` reads several of those (`scripts/check-steps.mjs`):

| Step | Reads, outside the digest |
| --- | --- |
| `bench:typecheck` | `bench/` |
| `lint`, `format` (`prettier --check .`) | `bench/`, `README.md`, `CONTRIBUTING.md`, `.github/**`, `.claude/**/*.md`, `.changeset/*.md` |
| `readme:check` | `README.md` |
| `api-extractor:check` | `etc/react-native-nitro-ui.api.md` |

Suppose `main` has moved only in those paths since a task branched. A typical case is another
merge adding a README row. The merge branch's code tree then equals the task branch's, and the
task branch's `check` counts. The merged `README.md` and `bench/` are never checked.

Within one branch the same gap already existed: a README-only or bench-only commit keeps `check`
green. But a fresh merge branch used to re-run `check` on the merged files, and now it does not.

The fix is one of two options, and the brief's "check is keyed to the full tree" makes this the
orchestrator's choice:

- **(a)** Record a second digest on `check` lines over every non-ignored file, docs and `bench/`
  included (`ls-files --cached --others --exclude-standard`, no `isCodeFile` filter), and compare
  that one for foreign `check` lines.
- **(b)** Never take `check` from another branch. It costs under 2 minutes.

I recommend (b): it is the smaller change and has no edge cases. Either way, `gates.md:130` has
to say what `check` is keyed to.

**M3. Runs relaxed by environment switches count on every branch.**
None of these is on the ledger line, and before this change each relaxed run counted only on
the branch that set it:

- `NITRO_UI_ALLOW_UNSTAMPED=1` (`example/rn-harness.config.mjs:99`): with no built artifact in
  the worktree, the harness skips the stamp check and tests whatever app the device has. That
  may be another worktree's build of other code. The config itself prints that such a run
  "proves nothing about any app in this checkout", yet the run records `pass` against this
  worktree's digest, and that pass now counts clone-wide.
- `NITRO_UI_ALLOW_LOCALE_MISMATCH=1` (`scripts/harness-run-state.js:42`): the locale-dependent
  conformance rows stop comparing, so a run in another locale passes rows it would fail.
- `NITRO_UI_GATE_METRO_FORCE=1` (`scripts/gate.mjs:1443`): the run starts on a Metro port another
  process already serves. The app can load another tree's JS bundle.
- `NITRO_UI_GATE_DEVICE_FORCE=1` (`scripts/gate.mjs:1244`): the run claims a device another live
  run holds. The other run can install its own app mid-run.

Lower risk, but they loosen a run: `HARNESS_TEST_TIMEOUT` (`rn-harness.config.mjs:317`),
`REAL_INPUT_TIMEOUT`, and `CI=true`, which raises the harness start timeouts.

`HARNESS_APP_PATH` is not a relaxation: `assertFreshApp` still checks the stamp, path and
fingerprint against this checkout.

The fix:

- Record the switches each run had set as `relaxed: {NAME: value}`, `{}` when none, on every
  line.
- Do not copy a line with any switch set into the clone-wide record.
- Have `foreignProofKey` refuse a line whose `relaxed` is missing or not empty, so lines written
  before the fix never count from elsewhere.
- Show `relaxed` in `status` and `table`.
- Red proof: a foreign line with `relaxed: {NITRO_UI_ALLOW_UNSTAMPED: '1'}` is accepted when the
  check is removed.

**M4. A device run counts on a branch whose gate code judges pass and fail differently.**
`scripts/gate.mjs`, `scripts/gate-core.mjs` and `scripts/gate-runner.mjs` decide `result`: the
exit code, `ranNothing`, the isolated-suite rule and `completeRerun`. `scripts/lease.mjs` and
`scripts/lease-core.mjs` decide which device a run addresses, and the harness config and the
Android runner import them. All five are on the check-only list (`gate-core.mjs:63-108`), so
they are in no device digest.

Two consequences:

- **A tooling change is never judged on devices before merge.** A change that tightens how a run
  is judged, or that breaks the supervisor's exit code, has the same device digests as `main`.
  It now merges on device greens judged by other gate code. A fresh merge branch used to force
  one full device run under the merged tooling.
- **Greens judged by broken code leak clone-wide.** An experimental branch whose gate code
  mis-judges, for example while proving a test red by mutating it, can record greens that every
  branch accepts.

The fix:

- Record `judge`, a digest of the check-only files a device run executes or that decide its
  result (at least the five above), on every line.
- Have `foreignProofKey` require it to equal the current one. `check` needs nothing extra,
  because its full tree already holds these files.
- Add a test that fails when a file `gate.mjs` or the device runners import is on the
  check-only list but missing from `judge`.
- Red proof: a foreign green with a different `judge` is accepted when the comparison is
  removed.

## Nice to have

- **N1.** Across branches, a newer red on the identical digest does not void an older green from
  another branch, including this branch's own older green. In-branch the newest line decides.
  Two branches running the same gate concurrently, one green and one red, read green everywhere.
  Brief item 3 says this branch's line wins, so this is the orchestrator's call. My
  recommendation: a newer full unmoved red elsewhere on the current digest makes the row
  "missing (red on `task/x`)", not green. `gate-core.mjs:849-879`.
- **N2.** `foreignProofKey` never reads `v`. Lines from a newer ledger version are accepted
  whatever their new fields mean, so a later "do not count" marker would be ignored by branches
  cut before it. Accept foreign lines only when `entry.v === LEDGER_VERSION`, and bump the
  version with M3/M4. `gate-core.mjs:785`.
- **N3.** Point 2c.
  - **What ties a run to its binary:** the `app.stamp` check at harness start. It compares the
    stamp's tree, artifact path and fingerprint with the recording worktree's full code tree.
    `real-input:ios` builds and stamps its own app; `real-input:android` calls `assertFreshApp`.
    Digest equality carries that tie to another branch exactly as it carries it across commits
    within one, so a run that is not relaxed is tied as strongly across worktrees.
  - **What no digest or line holds:** the stamp's fingerprint, the `node_modules` install (Metro
    bundles from it, Pods build from it), the simulator runtime or AVD API level, and the Xcode
    version. Each worktree has its own `node_modules`, so a stale install in one worktree now
    reaches every branch.
  - **Recommendation:** record the stamp fingerprint, a hash of the installed lock (for example
    `node_modules/.bun-tag` or bun's install snapshot) and the device runtime on device lines,
    and refuse foreign lines that differ.
- **N4.** The clone-wide record is never pruned. At the current rate, about 31 runs a day at
  about 3 KB each, it grows by roughly 35 MB a year, and `need`, `status` and `table` parse all
  of it on every call. Copy a slim line (drop `suiteTimings`, `stepTimings`, `summaries` and
  `load`) and prune lines that can no longer prove anything: red, filtered or moved runs, and
  digests superseded on their branch. Privacy is fine: lines hold device UDIDs, emulator
  serials, lease ids, the HEAD sha, the branch and a store-relative log path, with no absolute
  path or hostname. That is the same content as the gitignored `.gates/` ledger, and it is
  inside `.git` and never pushed.
- **N5.** Two harness runs in one worktree still share two files:
  - `example/.harness/manifest.js`, which upstream truncates and rewrites at each start
    (`@react-native-harness/bundler-metro/dist/manifest.js`).
  - Metro's file cache, `example/.harness/cache/metro`. Upstream `FileStore` writes in place,
    without write-and-rename (`metro-cache/src/stores/FileStore.js:57`).

  Losing either race gives a bundle without `RN_HARNESS`, a transform error, or a reload with
  identical content: a red or a flake, never a false green. Name both in `gates.md` as a flake
  source when the two harness gates run together. Separately, the run-state change is sound:
  - **Separate worktrees:** each has its own `example/`, so their files never collide.
  - **The same port twice:** the Metro pre-flight refuses it unless forced.
  - **A stale file from a killed run:** it is overwritten at the next start, and readers reject
    one older than 15 s.
  - **Real-input and a hand-started Metro:** both get a 404 from the route, which reads as
    strict, the same outcome as before.
- **N6.** `harness-run-state.test.js` fakes `req.socket.localPort`. The device runs do not prove
  the route either: a 404 reads as "no opt-out", which passes in the pinned locale. Add one test
  that starts a real `http` server on an ephemeral port with `withRunStateRoute` and fetches the
  state.
- **N7.** Two refusals have tests but no red proof in the report: the full-tree comparison for
  foreign `check` (`gate-core.mjs:804`) and the red-run refusal (`:786`). The digest-differs
  mutation only touches the device branch at `:808`.
- **N8.** `CONTRIBUTING.md:596`, `:612` and `:779` were edited without re-wrapping, leaving
  lines of about 130 characters among lines of about 100.
- **N9.** Every detached worktree writes to one `detached.jsonl` in the clone-wide record, and
  its rows read "from `detached`". This is harmless, but naming the HEAD sha would be clearer.

## Point by point

1. **Lines from another branch, and what refuses each.**
   - **A different digest:** `gate-core.mjs:808`, and `:804` for `check`.
   - **No per-gate digest:** `:808` (`got` is `null`).
   - **A filtered run:** recorded under its own name, so `listByGate` keys it apart and `:785`
     refuses it. A full name with a filter command is refused at `:795`.
   - **A red run:** `:786`. But see M1.
   - **A tree that moved while it ran:** `:787` for the full tree, `:809` for the gate digest.
   - **A completion whose red run was on another digest:** `completeRerun` (`:2333-2337`) records
     it as `fail`, so `:786` refuses it, and the completion's own digest must match at `:808`.
   - **Malformed or half-written JSON:** `parseLedger` marks it corrupt, `readEvidence` drops it
     (`gate.mjs:498`) and `:785` refuses it again.
     - **The append:** a single `appendFileSync` with `O_APPEND` on a local disk, so one
       `write(2)` per line, and lines do not interleave.
     - **Who appends to one file at once:** only writers on the same branch. That is now real
       for two harness gates in one worktree, and for detached worktrees.
     - **A torn tail:** it joins the next line and both read as corrupt. Evidence is lost, never
       a false green.
   - **A gate name that only starts with the gate's name:** `:785` compares names exactly.
   - **A branch name with separators or dots:** `ledgerFileName` (`:1337`) refuses `..`, a
     leading `/` and NUL, and git refuses components that start with `.`. `ledgersUnder`
     recovers the branch from the nested path.
   - **An older ledger version:** refused at `:808` and `:809`.
   - **A newer ledger version:** accepted (N2).
