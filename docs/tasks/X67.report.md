# X67 — the press-feedback check reads the row while the finger is down, however slow the driver

**Branch:** `task/X67-press-feedback-held-frames` (from `main` at `b93d3b60`) · **Round:** 1 of up to 3 ·
**Lease:** `X67-3v1t6` (`emulator-5570` / Metro `9293`)

## Summary

`pressPaintsFeedback` read one frame 450 ms after it issued an 1800 ms press. On a hosted
runner the driver sometimes takes about a second to put the finger down: the failing press took
2777 ms from request to answer, against 2000 to 2200 ms for the other 1800 ms presses in the
same run. The frame was taken before the touch, so the row read exactly as at rest (0.9700
against 0.9700).

The check now reads frames from +450 ms until one shows ink or the press ends. A frame counts
only if its read finished less than 1800 ms after the press was issued. The finger goes down no
earlier than the issue and stays down 1800 ms, so a counted frame was certainly taken before the
lift. A frame that finished later can show ink fading after the lift, so it is listed in the
failure message and not counted. The minimum drop, the hold time and the check that the ink
clears after the lift are unchanged. The counting rule is `heldDrop`, unit-tested with the
failing run's timings.
