# X66 — the real-input suite finds a field by its name whether the driver nests the name or not

**Branch:** `task/X66-form-field-locator` (from `main` at `1479176e`) · **Round:** 1 of up to 3 ·
**Lease:** `X66-a6mqy` (`emulator-5570` / Metro `9293`)

## Summary

`editableField(screen, label)` now returns a handle that resolves the field again on every
call. It tries nesting first and then geometry, and acts through an engine locator, so no box
is ever frozen. The handle lives in `example/e2e/real-input/field-locator.ts`:

- **Nesting:** `editables.filter({ has: named })`, one count. With one editable node on the
  screen (Form), it acts through `editables.nth(0)`, so the name moving beside the field between
  the count and the action changes nothing.
- **Geometry fallback:** the editable node whose box holds a named node's box (1 px slack). The
  candidates are first narrowed by one expression: the editable nodes inside the innermost group
  that holds both the name and an editable node. All editable nodes are measured only when that
  finds none.
- **Not found:** waits up to the engine's action timeout, then fails with "matched no nodes"
  wording, so `boxOf` and `reveal` read it as absent.
- **Two candidates:** an ambiguity error, never a guess.

Decision for the reviewer: **read cost is part of the contract.** The first device run, which
read every field's box, failed all three TextField tests. `reveal` checks that a box holds
still with two reads inside 2 s, and on a seven-field screen one resolve took about 20
snapshots. The final version resolves in 2 snapshots (nested) or 5 (beside). An action within
1 s of a resolve reuses the locator that resolve chose, so a count followed by a read costs one
resolve. A unit test pins both numbers.

The handle is a `Proxy` typed as `Locator`; chaining it or passing it to `expect` throws a
clear error, and no caller does either.

`e2e.config.ts` now reads `actionTimeout` from `example/e2e/timeouts.ts`, so the handle's wait
and the engine's wait are one number. The value is unchanged at 30 s. No assertion, timeout or
retry setting changed.

The unit test's stand-in screen resolves expressions as the mobile engine does. Its sibling fixture is the CI failure's own tree and boxes;
its nested fixture is this machine's dump.

The first local run showed the sibling shape too, so it is not CI-only.

Caveat on the CI evidence: at failure, the case's own evidence line counted
`getByRole('textbox')` as 0 as well. A read in that state finds no editable node in either shape,
and this change cannot help it (follow-up below).
