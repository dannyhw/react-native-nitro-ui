## What was checked

**The iOS stall timer cannot cut short a healthy run.** The timer starts when
`test-without-building` is spawned, and the first `Test Case '-[...]' started` line disarms it.
The regex matches the real lines in `.real-input/ios/xcodebuild-test.log` and every method a
run can select, including `testRealInputA11y` (an `--a11y`-only run) and
`testRealInputTabTargets` (`--tab-targets`). XCTest prints `started` before `setUp`, so app
launch and Metro bundling happen after the timer is disarmed. A slow first case cannot trip it.

**The "2 minutes" are build time.** In the filtered `--control switch` run:

| Time | Event |
| --- | --- |
| 09:08:30 | The gate starts |
| about 09:08:35 to 09:09:20 | `build-for-testing` (incremental), then `simctl install` |
| 09:09:31.9 | `test-without-building` starts, from xcodebuild's own `116.501 elapsed -- Testing started` line ending at 09:11:28.4 |
| 09:09:37.0 | The runner prints `Running tests...` |
| 09:09:40.98 | The first case starts |

So the timer saw about 9 s at load about 20. The rest happens before the timer is armed. Even at
load 100+, nothing measured here comes near 5 minutes: 5 minutes is about 30 times the observed
time.

**Stopping.**
- `xcrun simctl terminate <leased udid> nitroui.example.uitests.xctrunner`. That is the built
  runner's real `CFBundleIdentifier`.
- Then `child.kill('SIGINT')` and, after 30 s, `SIGKILL`, both to the one pid this call spawned.
  Nothing is stopped by name or pattern.
- `runXcodebuild` resolves only on `exit`, so the xcodebuild is gone before `ios.mjs` throws.
  The throw sets exit code 1 with the brief's message (no test started, the test service is not
  answering, restart the simulator), and leaves no per-unit report. As `gates.md` says,
  `--rerun-failed` then refuses.

**Android.**
- A run with no arguments still reads every case.
- `--control`-only keeps the whole sweep. This matches brief item 2 ("as it does today") and is
  documented. It differs from iOS, where `--control X` reads only X's case. The combined form
  matches iOS.
- A failed control still plans exactly `--control X`, and that run still reads the whole sweep.
  Today the sweep cases were every-run checks; they are now passing units, and a failure in the
  re-run still reaches the exit code. The behaviour is the same.
- Mixed failures plan `--control X --a11y Y`, which reads Y plus X's case
  (`realInputFilterArgs` + `androidRunPlan`).
- Tree checks are all `<control> (tree)`, so an `--a11y`-only completion leaves no every-run
  check unproven.

**Docs.** They are impersonal, in the present tense, and name no task ids.

## Findings

**N1. A wedged CoreSimulator can still hang the stall stop.** `scripts/real-input/ios-xcodebuild.mjs:92`, with `onStall` at `scripts/real-input/ios.mjs:404`.
- `onStall` runs `simctl terminate` through `spawnSync` with no timeout, before the SIGINT.
- Failure scenario: CoreSimulatorService stops answering, not only the test service inside the
  simulator. `simctl terminate` then blocks the event loop, xcodebuild never gets its SIGINT, and
  the gate hangs as it did before.
- The `finally` block's `clearJsLocation` (`simctl spawn`) has the same exposure, so this is not
  new risk.
- Fix: SIGINT first, or a `timeout` on the terminate.

**N2. `--rerun-failed` on a red Android `a11y:debt` spends a device run that cannot go green.** `scripts/real-input/a11y-sweep.mjs:146-157`.
- The debt check now records `--a11y <case>` arguments, but it is only emitted while it fails.
- In the re-run, either the row is still stale (failed again), or the problem reappears and the
  check is absent ("a11y:debt did not run"). Either way the completion is red.
- Before this change, Android refused up front with "which no filter selects".
- This is the same gap as the open iOS follow-up on `a11y:ios-debt`. Fix both in
  `planRerunFailed`.

**N3. No test covers a mixed failure.** `scripts/__tests__/real-input-android-run.test.js`.
- Nothing checks a red run with one failed control and one failed a11y case.
- From the code, the plan is right: `--control X --a11y Y`, and the run reads Y plus X's case.
- Failure scenario: a later change to `realInputFilterArgs` or `androidRunPlan` that drops
  either half would not be caught.

**N4. Two files still say the a11y filter is iOS-only.** `AGENTS.md:74` and
`.claude/skills/brief/SKILL.md:63` say "on iOS `--a11y <case>`". The flag now exists on both
platforms. Both files belong to the tooling owner, so this is a follow-up, not a fix round.

**N5. `AndroidRunPlan.full` is never read.** `scripts/real-input/android-run.mjs:76`.
`android.mjs` never reads `full`; only the tests assert it. It is a dead field.

**N6. An Android control completion still re-reads the whole sweep.** This is intentional and
inside the brief. The cost: a completion for one failed control is still exposed to every case's
flake, including the hosted DatePicker zero-sized read that motivated this task. This is a
follow-up only if the owner wants the iOS behaviour.
