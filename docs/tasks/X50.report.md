## Summary

Every ledger line is now also appended to `<git-common-dir>/nitro-ui-gate-evidence/<branch>.jsonl`.
Every worktree of the clone reads that record, and removing a worktree leaves it in place.
`need`, `status` and `table` take a gate as green from it only when this branch has no line of
its own that decides the gate on the current digest. When one does, the row names the branch
(`**PASS** (from \`task/x\`)`).

A line from elsewhere counts only if all of these hold (`foreignProofKey` in
`scripts/gate-core.mjs`):

- It is a merge gate that passed. A red line elsewhere never counts and never turns a row red.
- It is unfiltered: its command is the gate's own unfiltered command. A completion counts if
  it names the full run it completed, and it still shows as completed.
- Its digest for that gate equals the current one, with no fallback. `check` uses the full
  tree. A line with no per-gate digest, written before those digests existed, never counts
  from elsewhere.
- The tree and the gate digest read after the run equal the ones read before it. A line
  missing that second reading never counts.

Where I was unsure whether a run could count, it does not. Lines of this branch keep their old
rules, older formats included (item 6). `--rerun-failed` still plans from this branch's ledger
only (item 4).

Item 5: the harness run state is one file per Metro port (`example/harness-run/state-<port>.json`).
The Metro route serves the file for the port the request arrived on (`req.socket.localPort`).
So `harness:ios` and `harness:android` no longer read or remove each other's state. On devices
I built both apps, then started both gates 1 s apart under one lease. Both passed (rows below).
Wall clock was 18 m 20 s (20:51:06.9 to 21:09:26.8 UTC), against 32 m 53 s for the two
durations added together. Each run took the load of the other beside it, so these durations
are not sequential baselines.

  `gateTreesAfter` checks removed -> `✕ proves nothing when the tree, or the gate digest, moved…`

## Follow-ups

- harness: react-native-harness rewrites its manifest file (gitignored, under the example app) at each start. The
  content is identical for both platforms, but the truncate-then-write is a tiny race when two
  harness runs start together.
- gate: a run's relaxing environment (`NITRO_UI_ALLOW_LOCALE_MISMATCH`,
  `NITRO_UI_ALLOW_UNSTAMPED`) is not on its ledger line. Such a run counts like any other, now
  on other branches too.
- gate: tooling is outside the device digests. A green run counts here even if its branch had
  a different `gate.mjs` judging pass and fail.
- gate: lines recorded before this change in other worktrees' `.gates/` are not imported. They
  still count only on their own branch.
- gate: the clone-wide record is never pruned. It grows by one line per run.
