## Summary

`tree()` in `example/e2e/real-input/os-tree.ts` no longer reads the driver's snapshot from a
pipe. It makes a directory under the OS temp directory (`mkdtempSync(tmpdir()/nitro-ui-tree-)`),
opens `snapshot.json` in it and passes that file descriptor as the child's stdout. Node writes to
a file synchronously, so the driver's `exitAfterFlush` can call `process.exit` without cutting
off the answer. The read then loads the file and removes the directory in a `finally`, so it is
removed whether the read passes or fails, and nothing is written inside the repository.

Everything else stays as it was: the same argv (`snapshot --json --force-full --serial <serial>
--session e2e-android-0`, plus `--raw` when unmerged), the 60 s timeout, stderr still on a pipe
so a failure's message still carries the driver's stderr, the same two error texts, and the same
node mapping. The parse error's byte count is now the answer's length in bytes, not in UTF-16
characters.

The binary can be swapped through an optional second parameter, `tree(options, driver =
driverBinary())`. Every suite caller passes one argument, so the suite's normal path cannot
reach the override, and no environment variable was added.

`scripts/__tests__/os-tree-read.test.js` writes stand-in driver scripts to a test temp directory
and points `TMPDIR` at a second directory it owns, so it can see that directory empty after
each read. It covers:
- a 30 000-node snapshot of about 6 MB, printed with one `process.stdout.write` and an
  immediate `process.exit(0)`, read whole
- the argv the driver receives, with and without `unmerged`
- a cut-off answer that throws with its byte count (28)
- a non-zero exit that throws "failed" with the driver's stderr in the message

The last three cases also check that the temp directory is left empty.
