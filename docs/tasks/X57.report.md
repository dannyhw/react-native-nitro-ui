## Summary

The Android real-input verdict moved out of `scripts/real-input/android.mjs`, which starts a run
on import, into `scripts/real-input/android-results.mjs`, so it can be tested against e2e report
fixtures. `android.mjs` now passes it the text of `docs/tasks/FOLLOWUPS.md` and a reader for the
test files.

A skipped test counts as quarantined only when all of these hold:

- e2e skipped it as `explicit`, meaning `test.skip`. A runner skip such as
  `serial-predecessor-failed` stays red.
- The report's source line is a `test.skip(` line.
- The `//` comment block directly above that line contains `QUARANTINED <YYYY-MM-DD>`.
- The file name and the quoted title appear in a list item under "## Quarantined tests" in
  FOLLOWUPS. Wrapped items are read, and the section ends at the next heading.

A quarantined test prints `    QUARANTINED <title> — skipped, listed in docs/tasks/FOLLOWUPS.md`
on its own line, plus a count and list above the summary line, and leaves its control's verdict
to the other tests. Any other skip stays a `✗` line, `skipped, which is not a pass: …`, with one
reason per missing part. A control whose file collected no test is still `missing` and red.

`--rerun-failed` needed no gate-core change. The control's unit is `pass` when its only
non-passing test is quarantined, so `planRerunFailed` leaves it out. A test proves this through
`realInputUnitsFromResults` and `planRerunFailed`.

One decision for the reviewer: a control whose tests are all quarantined passes with no check
behind it. It does show its `QUARANTINED` lines. The brief's "decided by the other tests" does
not cover this case.

The icon provenance loop now uses the test's existing recursive `walk()` for every
`EXAMPLE_ICON_DIRS` folder.

`docs/agents/gates.md` gets one bullet under "Completing a red run". The flake skill needed no
change.
