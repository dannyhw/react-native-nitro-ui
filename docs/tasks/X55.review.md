## What was checked

- **Reap through a stale row (real pool).** `avd:x16_avd` (no `bootedAtMs`, `lastUsedMs` older)
  and `avd:nitroui_a` (lease X54, newer) both name `emulator-5574`. `serialHolder` marks x16
  stale whether or not X54 is live. The plan pass and the `canActOnKey` re-check both refuse it,
  so a reap never acts through x16. Even before this change, `shutdownDevice` asks the emulator
  `emu avd name` and refuses on a mismatch, so the new rule adds a second layer of protection.
- **The live device is still reaped when idle.** After X54 ends, `serialHolder(nitroui_a)` finds
  no hold on x16 and no newer record, so it returns `null` and the normal idle rule applies.
  A row can only get a newer timestamp than the live device's row through `notePair`, `claim` or
  `releaseClaim`, and all three act only on keys that `devices.json` declares. So an undeclared
  stale row cannot overtake the live one.
- **Pool restart.** When the pool restarts a device, `markBooting` keeps the old timestamps but
  sets `phase: booting`, which counts as a hold. `notePair` then writes `lastUsedMs = now`. When
  the timestamps are missing or tied on both rows, the result is `null` for both, which is the
  behaviour before this change (covered by the twin test).
- **Working directory.** `workDir()` creates `home` before each spawn. `bootEmulator` already
  wrote its log under `home`. Every binary is either absolute (the test stubs use
  `join(home, …)`) or found on `PATH`. No adb or emulator argument is a relative path. Nothing
  depends on the caller's working directory.
- **Lease notes.** An older `leases.json` with no `note` field prints as before
  (`lease.note != null`). Both `note` and the already-held path of `acquire --note` write under
  `paths.lock`, the same lock as `acquire` and `release`. `list --json` spreads the lease, so
  `note` appears in it.
- **Watchdog.** If `origin/main` is missing, `rev-list` fails, the function returns `null` and
  no fact is reported. A detached HEAD resolves. A first run that finds the checkout up to date
  writes an `ok` fact and is not reported (`diffSnapshot`: `old == null`, `level === 'ok'`), so
  merging this does not cost one non-quiet watchdog run.
- **Task records.** HEAD's branch is left out of `isOpen` and `live`. The new reason only comes
  into play when no other worktree or live branch keeps the task. A worktree on HEAD's own
  branch now falls through to the HEAD rule, which keeps the task anyway.

## Findings

1. **N** `.claude/skills/orchestrate/SKILL.md:105`: the example `merge/x55` puts a task ID in a
   skill, which must stay impersonal. A reader copies a stale ID into a branch name. Use
   `merge/train` alone or `merge/<topic>`.
2. **N** `scripts/__tests__/device-pool.test.js:1717`: no test reaps the idle live row while an
   older stale row shares its serial. That is the direction that matters for "an idle device is
   still powered off". The existing cases only assert `summary().stale === null` for the holder.
   Failure scenario: a later edit makes `reap` consult the holder another way, for example
   refusing any row whose serial appears twice. `nitroui_a` would then never be reaped, and no
   test goes red. Add one case: an x16-shaped stale row (no `bootedAtMs`), plus `nitro-ui-a`
   idle past its limit with no lease, and expect `avd:nitro-ui-a` in `reaped`.
3. **N** `scripts/device-pool.mjs:210`: two rows that both carry the same live lease each name
   the other as holder, so both are stale. Scenario: `devices.json` changes a pair's AVD while
   that pair's lease is live, and the lease then boots the new AVD on the same port. `list`
   marks both rows `stale:`, each pointing at the other. The reap outcome is unchanged because
   the lease keeps both rows anyway, and once the lease ends the timestamps settle it. Only the
   `list` wording is wrong.
4. **N** `scripts/watchdog-core.mjs:102`: the advice `git merge --ff-only origin/main` fails
   with "Not possible to fast-forward" when the checkout has commits of its own. The count is
   also relative to the last fetch, which the watchdog never does. A wording like "it lacks N
   commits of origin/main as last fetched" would match what is measured.
