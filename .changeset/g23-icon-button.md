`IconButton`: one glyph as a control, on both platforms — and its toggle form.

- **It is a `Button` with no label, so its name is a prop.** `accessibilityLabel` is required in the type, and empty warns in development: an icon button has no text, so a missing label is a control VoiceOver and TalkBack announce as "button". `<IconButton accessibilityLabel="Search" systemImage="magnifyingglass" androidIcon={require('./icons/search.xml')} onPress={openSearch} />` draws an SF Symbol on iOS and your own vector drawable on Android, each platform ignoring the other's prop, exactly as `Button`'s `systemImage` / `androidIcon` do — same glyph slot, same size ladder, same rules about what an unresolvable file costs (nothing but the glyph).
- **`variant` is Material's four icon buttons, by Material's names**: `standard` (a bare glyph, no container), `filled`, `tonal`, `outlined`. Android composes `IconButton`, `FilledIconButton`, `FilledTonalIconButton` and `OutlinedIconButton` with their own colour roles and their per-size pressed shapes. iOS has no icon-button control, so it draws a `Button` whose label is `.iconOnly` and maps the four looks onto its four button styles; the measured box of every rung is in `docs/components/icon-button.md` — Android's for all four variants, iOS's for `standard`, with its bordered variants measured where the ladder test can see the two forms differ — which is the honest place to see that iOS's `outlined` is a `.bordered` button with a hairline rather than a copy of Material's ring.
- **A toggle is the same control with a value**: pass `checked` / `defaultChecked` / `onCheckedChange` and it becomes Material's `…IconToggleButton` on Android and a `Toggle(…).toggleStyle(.button)` on iOS. It is on the same handshake as `Switch` and `Chip`: the tap is painted optimistically, the value React pushes afterwards is the one that stays, and a controlled toggle that refuses a flip reverts instead of drifting. Its two states are one box — a selection repaints an icon button and moves nothing, so a list of them does not re-measure.
- **`size` is the shared ladder** (`small` … `xxlarge`), and on Android a rung _is_ Material's own container token, so `small`=XS (32 dp), `medium`=S (40), `large`=M (56), `xlarge`=L (96), `xxlarge`=XL (136). Material will not publish a touch target below 48 dp, so the two smallest rungs are laid out in a larger box than the token they are drawn from — measured, not assumed. `width` (`narrow` / `uniform` / `wide`) is Material's three width options for a rung and is **Android-only**: it costs width and never height there, and iOS — whose box is the symbol plus its style's own padding — keeps one box for all three. `shape` is `Button`'s, with the same meaning. Both platforms floor the laid-out box at their own minimum target — Material's 48 dp on Android, Apple's 44 pt on iOS — so a `small` IconButton is a 20 pt glyph **inside** a 44 pt target rather than a 20 pt control, and iOS reaches that target for the styles that draw a bezel with a tappable layer behind the control instead of a wider bezel.
