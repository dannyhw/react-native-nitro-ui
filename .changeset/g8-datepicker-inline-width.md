The Android `inline` / `wheel` `DatePicker`'s calendar is no longer clipped inside a box narrower than 360 dp. Material 3 lays its seven weekday columns out with `Arrangement.SpaceEvenly` and gives each one `LocalMinimumInteractiveComponentSize` — 48 dp by default — so the grid needs 7 × 48 + 2 × 12 = **360 dp**, and in a narrower box the columns past the squeeze lose width rather than the box growing: `Modifier.size` enforces the incoming maximum, and an `inline` picker is a `fillWidth` control, so it is measured _at_ its box's width and nothing ever asks for more. At the 320 dp the README story and the example use, the header columns measured 126 px six times and then 20 px — Saturday at 7.6 dp — with each day's own 40 dp disc drawn wider than the cell holding it, overlapping its neighbour. The inline calendar now provides Material with its **40 dp day cell** (`DateContainerWidth`, the token the cell is drawn at) instead of 48 dp of interactive padding, which is what iOS's own inline calendar does at the same width: the grid needs 304 dp, so 320 dp fits and all seven columns are equal. Nothing is gained where nothing was being delivered — a squeezed cell was neither 48 dp nor 40 dp — and below the grid's own 304 dp minimum it is still clipped at the right, which is a box too small for its content saying so rather than a touch target scaled away. `compact` is unchanged: its dialog is a window laid out at Material's 360 dp.
