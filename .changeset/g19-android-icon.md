`Button` gains `androidIcon`, and the size ladder gains `xlarge` and `xxlarge`.

- **`androidIcon` is Android's counterpart to `systemImage`.** `<Button title="Share" systemImage="square.and.arrow.up" androidIcon={require('./icons/share.xml')} />` draws an SF Symbol on iOS and your own vector drawable on Android, with each platform ignoring the other's prop. The icon takes the control's own text colour, so it follows the variant, `enabled` and `tintColor`, and it is sized by the size ladder — the same numbers the label beside it is read from. Each file is loaded once per process and shared, so a list of forty rows with the same icon rasterises it once. `docs/components/button.md`, "Android icons", has the file, where to get Material Symbols, and the failure table.
- **An icon is a file the app imports.** `androidIcon` takes a vector drawable the way `<Image>` takes a picture: `androidIcon={require('./icons/share.xml')}`. Metro carries that file, so there is no setup step to document and no plugin to register — in a release build the `.xml` becomes an ordinary drawable resource (named the way React Native files any bundled asset, `src_assets_icons_share` for `src/assets/icons/share.xml`), and in development nitro-ui loads it from the dev server itself, because React Native deliberately will not serve Android `.xml` assets. It does that by building the Metro URL and reading the file natively — off the main thread, parsed into a Compose `ImageVector`, cached per URL for the process — and it never registers a custom source transformer, because that would change how every `Image` in your app resolves its sources. Round 1's drawable-name form still works (`androidIcon="share"` for `res/drawable/share.xml`), and so does every rule that came with it.
- **The icon's size comes from the size ladder, never from the file.** The slot is `iconSizeFor(size)` wide and the label is laid out beside it, both read from the rung that sets the control's height, so the first frame of a development build already has the box: while the file is being read the slot is reserved and empty, the glyph appears in it, and nothing moves. Artwork that cannot be resolved — a name that is not in the resource table, a 404 from the dev server, a file that is not a `<vector>`, an asset that is a `.png` — draws nothing and reserves nothing, exactly the no-icon control, and says so once.
- **`size` now has five rungs.** `xlarge` and `xxlarge` are Material 3's own L and XL container heights (96 and 136 dp), so the ladder has the five rungs the tokens publish and Material's XS–XL button row is this ladder under other names — `small`=XS, `medium`=S, `large`=M, `xlarge`=L, `xxlarge`=XL. iOS draws four button sizes, so the top two rungs are both `.extraLarge` (iOS 17+) and `.large` before it: five rungs on Android, three distinguishable on iOS. The three rungs that already existed are unchanged.
