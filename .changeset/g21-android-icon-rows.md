`androidIcon` on menu rows and on `Chip` — the glyph prop, everywhere a leading glyph lives.

- **A row of a `Menu`'s or `ContextMenu`'s `group` takes `androidIcon`**, in either form the prop already has: `require('./icons/share.xml')` or a drawable name (`docs/components/button.md`, "Android icons"). A submenu's label row does not take it — it is a group label on Android and a `UIMenu` title on iOS, with no slot on either. iOS draws `systemImage` and ignores this, Android the other way round, so a row that wants a glyph on both platforms names both and needs no `Platform.select` — `<MenuGroup actions={[{ id: 'share', title: 'Share', systemImage: 'square.and.arrow.up', androidIcon: require('./icons/share.xml') }]} />`.
- **Android hands the slot to Material.** A row with a glyph is a `DropdownMenuItem` with a `leadingIcon`: the size is `MenuDefaults.LeadingIconSize` — **20 dp**, not the 24 an icon looks like elsewhere — and the colour, the gap to the title and the group insets are Material's, read as the row draws so a disabled row dims its glyph the way it dims its title. On a `checked` row the leading check keeps that slot: the check is what the row _means_, and the menu is one width either way. A file that cannot be resolved reserves nothing, to the dp.
- **`Chip.androidIcon` is the same prop in `FilterChipDefaults.IconSize`** — 18 dp, the same size on both kinds. A selected filter chip's check mark takes the slot from the glyph, and because the check is the same 18 dp the swap never moves the box; a chip with no glyph is the one that grows by the check. `androidIcon` joins the chip's sizing key, so a chip that changes its glyph is measured again instead of laid out at the old glyph's width.
- **Measured as pixels, not as a prop echo.** A row is drawn in a popup of its own window, where nothing readable on the control says whether artwork reached the screen, so the harness samples that window and asserts the difference between a menu with the glyph and one without it is 20 dp squared at the device's density (18 dp for a chip) — with a filled square as the fixture, so the difference _is_ the slot's area. The colour is Material's from the device's dynamic palette, which a test cannot name: each row reports the colour it tinted its glyph with as it draws, and the test samples for that.
